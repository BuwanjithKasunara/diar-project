# Benchmarks and rules

Benchmarks are curated project knowledge, not validated hiring standards. Required/preferred skill names must resolve to the taxonomy.

Role-specific expectations make GitHub optional for Researcher and Entrepreneur. Project keywords indicate relevance, not quality. Certification matching checks listed benchmark names conservatively; equivalent credentials can be missed and need review.

Rules connect evidence, benchmark expectations, and visibility to explained suggestions. Unknown information prompts clarification rather than an asserted weakness.

Privacy Focused favours private portfolios/selective sharing; Semi-Public favours controlled exposure; Fully Public permits public showcasing. Résumé contact details do not prove public exposure. Pasted LinkedIn visibility is unverified unless supplied.

Version benchmark changes and document rationale. Substantive scoring/privacy changes require an [ADR](../adr/README.md).

Benchmark version 2 records this phase's optional-GitHub expectations for Researcher/Entrepreneur and taxonomy validation. API startup rejects unknown canonical benchmark skills. Rule R11 suggests stronger supporting profile sections only when LinkedIn is supplied, section coverage is sparse, and visibility is Fully Public; absent LinkedIn remains optional and generates clarification instead.
